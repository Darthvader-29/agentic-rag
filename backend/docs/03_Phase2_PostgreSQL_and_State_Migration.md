> pass before its commit. The tree stays releasable after every task. Companion to
> [`00_Master_Upgrade_Roadmap.md`](./00_Master_Upgrade_Roadmap.md) §4 (Phase 2) and follows
> [`02_Phase1_Async_IO_and_Dependency_Injection.md`](./02_Phase1_Async_IO_and_Dependency_Injection.md).
>
> **Doc numbering:** `00` = master roadmap; `01` = Phase 0; `02` = Phase 1; `03` = this Phase 2 detail doc.

## 1. Objective & scope

Make **PostgreSQL the operational source of truth** for session and document state, and **stop
abusing the vector store as a state store.** Today the app reconstructs "does this session have
documents?" and "which S3 keys belong to this session?" by firing dummy-vector `top_k=1000` queries
at Pinecone — slow, eventually-consistent, and broken under horizontal scale (roadmap §1, §3
ordering constraint 3). Phase 2 introduces a real relational schema, an async data-access layer, and
Alembic migrations, then **repoints those two state queries at Postgres** and reverts `PineconeClient`
to **pure vector search** (save / search / delete-by-session only).

This phase changes *where state lives*, not the product flow. The same routes, the same `route →
relevance → retrieve → generate` path, the same response shapes. What changes: upload now writes a
`sessions` row (idempotently) and a `documents` row; ingestion marks that document's status as it
progresses; cleanup deletes the rows; and "has documents / list keys" are answered by SQL, not by a
vector scan.

**In scope:**
- **Async SQLAlchemy 2.0 + `asyncpg`.** An `AsyncEngine` + `async_sessionmaker` built once in the
  FastAPI `lifespan` (alongside the Phase 1 clients on `app.state`), with an `AsyncSession` provided
  **per-request** via `Depends(get_db_session)` (new provider in `dependencies.py`).
- **`postgres` service** added to the existing `docker-compose.yml` (next to MinIO), and a
  `DATABASE_URL` field on the Pydantic `Settings` (`config.py`).
- **ORM models** in new `database/models.py` (a `DeclarativeBase` with `Mapped` / `mapped_column`
  typing): `sessions`, `documents` (with a `status` enum), and document ingestion status tracked via
  that enum (no separate jobs table — see §2).
- **Data-access layer** in new `database/repository.py`: async query functions
  (`get_or_create_session`, `create_document`, `set_document_status`, `session_has_documents`,
  `list_s3_keys_for_session`, `delete_session`).
- **Alembic** wired to the async URL: `alembic.ini`, `migrations/env.py`, and a first autogenerated
  migration creating the two tables + the enum.
- **Strip the state methods** (`has_session_documents`, `list_s3_keys_for_session`) off
  `PineconeClient`; repoint `router.route_query` and `app.cleanup_session` at the repository.
- **Wire upload / cleanup / ingestion** (`app.py`, `components/preprocessing.py`) to read & write
  Postgres through the injected session / repository.
- Repository-layer tests against a real test database, an Alembic upgrade-head migration test, and a
  CI assertion that **no dummy-vector state query remains** anywhere in the tree.

**Explicitly deferred** (do **not** do here):
- **Session/document ownership and the `users` table** — `session_id` stays client-supplied and
  unauthenticated for now; rebinding ownership to an authenticated user (and rejecting cross-user
  access) is **Phase 3**. Phase 2's `sessions` table is deliberately user-less; Phase 3 adds the
  `user_id` FK.
- **Multi-provider LLM abstraction / removing the Gemini global** — **Phase 4**. `generation.py` and
  the `router.py` Gemini globals are untouched.
- **Redis cache, Celery queue-based ingestion, S3 presigned uploads** — **Phase 5**. Ingestion still
  runs via FastAPI `BackgroundTasks`; we only add a status column it can update.
- **3-layer memory tables / knowledge graph** — **Phase 7**.

## 2. Decisions & rationale

| Decision | Rationale |
|---|---|
| **PostgreSQL as the operational source of truth** | Roadmap product decision §2.4. Vectors are for similarity search; relational state (which docs, which session, what status) belongs in a transactional store with real consistency, indexes, and FKs. |
| **Async SQLAlchemy 2.0 + `asyncpg` (no sync driver)** | The whole stack is `async def` (Phase 1). A sync `psycopg2` engine called from an async handler would re-introduce exactly the event-loop blocking Phase 1 removed. `asyncpg` + `AsyncEngine` keeps DB I/O on the loop natively. |
| **`AsyncEngine` in `lifespan`; `AsyncSession` per-request via `Depends`** | Mirrors the Phase 1 seam exactly: the *engine* (connection pool) is an expensive, long-lived singleton on `app.state`; a *session* is a cheap, per-request unit-of-work that must not be shared across requests/tasks. `get_db_session` yields one session and closes it (commit/rollback) per request. |
| **`status` enum column on `documents` (no separate jobs table)** | Roadmap §4 allows "an ingestion-job status table **or** a `status` enum on `documents`." One document = one ingestion job here; a `DocumentStatus` enum (`PENDING → PROCESSING → READY / FAILED`) captures the lifecycle without a second table to join. A jobs table is over-engineering until Celery (Phase 5) introduces retries/fan-out. |
| **Repository module (free async functions taking `AsyncSession`), not a class** | Keeps the data-access layer trivially testable (pass a test session) and avoids a stateful object competing with the session's own lifecycle. Each function does one query and returns plain values / ORM rows; the caller owns the transaction boundary. |
| **`PineconeClient` reverts to pure vector search** | The whole point of the phase. Pinecone keeps `save_vectors` / `search_vectors` / `delete_vectors_by_session` only. `has_session_documents` and `list_s3_keys_for_session` are **deleted** from it — they move to SQL where they belong. |
| **`get_or_create_session` is idempotent (upsert-on-conflict)** | `session_id` is client-generated (Phase 1 reality; ownership lands in Phase 3). Upload may be the first call for a session; creating the `sessions` row on conflict-do-nothing keeps it safe under concurrent first uploads. |
| **Alembic `env.py` runs migrations in **async** mode** | The models and URL are async (`postgresql+asyncpg://`). `env.py` uses `async_engine_from_config` + `connection.run_sync(...)` so `alembic upgrade head` works against the same driver CI and runtime use — no second sync URL to maintain. |
| **Dedicated test database + transactional rollback per test** | Repository tests need a real Postgres (SQLite can't honor the enum/FK semantics we rely on). Each test runs inside a transaction that is rolled back at teardown, so tests are isolated and fast and never leave residue. |
| **CASCADE delete from `sessions` → `documents`** | Cleanup deletes the session row; the FK `ondelete="CASCADE"` removes its documents atomically. One statement instead of a manual two-step that could partially fail. |

  `await pinecone.has_session_documents(session_id)` to decide whether to consult the vector store.

- **`app.py`** — has a `lifespan` and `Depends` wiring (Phase 1). `upload(...)` resolves
  `s3`/`embedder`/`pinecone`, does `s3_key = await s3.upload_fileobj(...)`, then
  `background_tasks.add_task(process_file_pipeline, s3_key, filename, session_id, s3, embedder,
  pinecone)`. `cleanup_session(...)` calls `await pinecone.list_s3_keys_for_session(...)`, then

  writes anywhere.**
- **`components/preprocessing.py`** — `process_file_pipeline(file_key, filename, session_id, s3,

  **No status tracking** — there is no record that a document exists or finished ingesting.
- **`config.py`** — single `pydantic-settings` `Settings`; Phase 1 added `ENVIRONMENT`
  (`Literal["development","production"]`) and `S3_ENDPOINT_URL`. **No `DATABASE_URL`.**
- **`docker-compose.yml`** — exists with `minio` + `createbuckets` services and a `minio_data`

- **`conftest.py`** — injects dummy secrets via `_DUMMY` before import; Phase 1 DI-override fixtures

- **Tests / CI:** async-path + DI-override tests pass; CI is Jenkins (`Jenkinsfile`); coverage floor

  migration test.
- **Deps:** `sqlalchemy`, `alembic`, `asyncpg` are **not yet present** (roadmap §6 lists them for
  this phase).

## 4. Risks & gotchas (with resolutions)

1. **A single `AsyncSession` shared across requests corrupts state.** Sessions are not concurrency-safe;
   sharing one across requests (or across a background task and its originating request) leaks
   identity-map state and breaks transactions. **Resolution:** the **engine** is the singleton on
   `app.state`; `get_db_session` yields a **fresh** `AsyncSession` per request from
   `async_sessionmaker(engine, expire_on_commit=False)` and closes it in a `finally`. The background
   ingestion task opens its **own** session from the same sessionmaker (gotcha 2).

2. **Background tasks can't use `Depends` (still true from Phase 1) — so they can't receive a
   request-scoped session.** `process_file_pipeline` runs *after* the response. **Resolution:** pass
   the **sessionmaker** (a callable on `app.state`, lifetime = app) into the background task and have
   it open/commit/close its own short-lived session: `async with session_factory() as db: ...`. Do
   **not** pass the request's session into the task — it is closed by the time the task runs.

3. **Async Alembic is fiddly.** `alembic init` scaffolds a **sync** `env.py`; pointing it at
   `postgresql+asyncpg://` with the default sync runner fails. **Resolution:** replace
   `migrations/env.py` `run_migrations_online()` with the async pattern
   (`async_engine_from_config` → `await connection.run_sync(do_run_migrations)`), and read the URL
   from `Settings.DATABASE_URL` (not a hard-coded `sqlalchemy.url` in `alembic.ini`). The migration
   test then just runs `alembic upgrade head` against the throwaway test DB.

4. **`Settings` requires `DATABASE_URL` at import, breaking pytest collection.** Like every other
   required secret, an absent `DATABASE_URL` makes `Settings()` raise at `import app`. **Resolution:**
   add `DATABASE_URL` to `conftest.py` `_DUMMY` (point it at the test Postgres) and to Jenkins
   `environment{}` / `.env.example`. Same pattern Phase 0/1 use for the other secrets.

5. **Enum drift between Python and Postgres.** A SQLAlchemy `Enum(DocumentStatus)` creates a Postgres
   `ENUM` type; later adding a member needs a migration (`ALTER TYPE ... ADD VALUE`), which Alembic
   does not autogenerate. **Resolution:** define `DocumentStatus` as a `str`-`enum.Enum`, map it with
   `SAEnum(DocumentStatus, name="document_status")`, and **note in the migration** that future enum
   members require a hand-written migration. The four members we ship cover the current lifecycle.

6. **Ingestion failure must not leave a document stuck in `PROCESSING`.** If embedding/upsert throws,
   the row would lie about its state. **Resolution:** `process_file_pipeline` wraps the pipeline in
   `try/except`; on success it sets `READY`, on failure it sets `FAILED` (and re-raises/logs). The
   status write is its own committed transaction so it survives even if the request is long gone.

7. **`top_k=1000` is a magic-string the grep gate keys on — make sure none survives.** The exit gate
   greps for `top_k=1000` and `[0.0] *` dummy-vector patterns. A stray reference (even in a comment or
   test fixture) fails CI. **Resolution:** delete the two methods entirely from `db_manager.py`,
   remove their Phase-1 tests, and ensure no docstring/comment re-introduces the literal. The grep
   gate (§5/§6) is the backstop.

8. **`expire_on_commit=True` (the default) detaches attributes after commit.** Returning an ORM
   object after `commit()` then reading `.s3_key` triggers a lazy reload on a closed session →
   `DetachedInstanceError` / implicit IO. **Resolution:** build the sessionmaker with
   `expire_on_commit=False`; repository functions that must return scalars after commit return plain
   Python values (e.g. `list[str]`, `bool`), not live ORM instances, where practical.

9. **CI needs a real Postgres, not SQLite.** We rely on FK `ON DELETE CASCADE`, the native `ENUM`
   type, and `asyncpg`. SQLite would silently diverge. **Resolution:** the Jenkins pipeline runs a
   `postgres` service container (or `docker compose up -d postgres`) and exports `DATABASE_URL` to it;
   the migration + repository tests run against that. The same `docker-compose.yml` `postgres`
   service serves local dev.

10. **Connection pool exhaustion under `to_thread` + DB.** The Phase 1 clients use the default thread
    pool; the DB uses its own async pool. **Resolution:** these pools are independent; set a modest
    `pool_size`/`max_overflow` on the engine and dispose it in `lifespan` shutdown
    (`await engine.dispose()`), so connections are released cleanly on restart.

### Task 2 — `database/models.py`: ORM models (DeclarativeBase, SQLAlchemy 2.0 typing)
**Files:** create `database/models.py`.

```python
import enum
import uuid
from datetime import datetime, timezone

from sqlalchemy import Enum as SAEnum, ForeignKey, String, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship


class Base(DeclarativeBase):
    pass


class DocumentStatus(str, enum.Enum):
    PENDING = "pending"
    PROCESSING = "processing"
    READY = "ready"
    FAILED = "failed"


def _uuid() -> str:
    return str(uuid.uuid4())


class Session(Base):
    __tablename__ = "sessions"

    # client-supplied session_id is the PK (ownership/user_id arrives in Phase 3)
    id: Mapped[str] = mapped_column(String(64), primary_key=True)
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())

    documents: Mapped[list["Document"]] = relationship(
        back_populates="session", cascade="all, delete-orphan", passive_deletes=True
    )


class Document(Base):
    __tablename__ = "documents"

    id: Mapped[str] = mapped_column(String(36), primary_key=True, default=_uuid)
    session_id: Mapped[str] = mapped_column(
        ForeignKey("sessions.id", ondelete="CASCADE"), index=True
    )
    s3_key: Mapped[str] = mapped_column(String(512), unique=True)
    filename: Mapped[str] = mapped_column(String(512))
    status: Mapped[DocumentStatus] = mapped_column(
        SAEnum(DocumentStatus, name="document_status"),
        default=DocumentStatus.PENDING,
        index=True,
    )
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(
        server_default=func.now(), onupdate=lambda: datetime.now(timezone.utc)
    )

    session: Mapped["Session"] = relationship(back_populates="documents")
```

**GREEN** — `database/repository.py`:
```python
from sqlalchemy import delete, exists, select, update
from sqlalchemy.dialects.postgresql import insert as pg_insert
from sqlalchemy.ext.asyncio import AsyncSession

from database.models import Document, DocumentStatus, Session


async def get_or_create_session(db: AsyncSession, session_id: str) -> None:
    stmt = pg_insert(Session).values(id=session_id).on_conflict_do_nothing(index_elements=["id"])
    await db.execute(stmt)


async def create_document(
    db: AsyncSession, *, session_id: str, s3_key: str, filename: str
) -> Document:
    doc = Document(session_id=session_id, s3_key=s3_key, filename=filename,
                   status=DocumentStatus.PENDING)
    db.add(doc)
    await db.flush()        # populate doc.id without ending the request transaction
    return doc


async def set_document_status(db: AsyncSession, *, s3_key: str, status: DocumentStatus) -> None:
    await db.execute(update(Document).where(Document.s3_key == s3_key).values(status=status))


async def session_has_documents(db: AsyncSession, session_id: str) -> bool:
    stmt = select(exists().where(Document.session_id == session_id))
    return bool(await db.scalar(stmt))


async def list_s3_keys_for_session(db: AsyncSession, session_id: str) -> list[str]:
    stmt = select(Document.s3_key).where(Document.session_id == session_id).order_by(Document.s3_key)
    return list(await db.scalars(stmt))


async def delete_session(db: AsyncSession, session_id: str) -> None:
    # FK ON DELETE CASCADE removes the session's documents
    await db.execute(delete(Session).where(Session.id == session_id))
```

```

├────────────────────────┤         ├─────────────────────────────────────┤
│ id            PK  str   │1      * │ id          PK  str (uuid)           │
│ created_at        ts    │────────<│ session_id  FK → sessions.id         │
└────────────────────────┘ CASCADE │             (ON DELETE CASCADE, idx) │
                                    │ s3_key          str  (UNIQUE)        │
                                    │ filename        str                  │
                                    │ status          document_status enum │
                                    │ created_at      ts                   │
                                    │ updated_at      ts                   │
                                    └─────────────────────────────────────┘

document_status ENUM: pending | processing | ready | failed
```

| Table | Column | Type | Notes |
|---|---|---|---|
| `sessions` | `id` | `varchar(64)` PK | client-supplied `session_id` (user_id FK added in Phase 3) |
| `sessions` | `created_at` | `timestamp` | `server_default=now()` |
| `documents` | `id` | `varchar(36)` PK | UUID string |
| `documents` | `session_id` | FK → `sessions.id` | `ON DELETE CASCADE`, indexed |
